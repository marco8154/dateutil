## Answers

**1. Independence.** `rrule_reference.py` imports nothing from `dateutil` — only `calendar` and `datetime` (rrule_reference.py:14-15). `test_rrule_reference.py` (l. 8-12) and `test_rrule_reference_setpos_prop.py` import stdlib plus `expand`; the latter imports `dateutil.rrule` only for the system under test (l. 17-19). The BYSETPOS part of `expand` (period start l. 90-93, `_select_positions` l. 158-169) does not resemble dateutil's `_iter`/`poslist`: dateutil builds `poslist` by appending then sorting (src/dateutil/rrule.py:791, 866-884), the reference selects by index from an already-ordered candidate list (rrule_reference.py:164-169). No structural copy found; the shared element is only input (anchored defaults from `dtstart`), not code.

**2. RFC fidelity.** `expand` follows RFC 5545 for BYSETPOS mechanics: one set per FREQ interval starting at the interval beginning (l. 2364-2370, implemented via `_period_start` at rrule_reference.py:144-155 and applied at l. 90-93), positions counted from period start (l. 2377-2380, `_select_positions` l. 158-169), out-of-range positions select nothing (l. 2370-2371), duplicates collapse once (`_select_positions` uses a set of indices, l. 164-169), input validated to ±1..±366 with a mandatory other BYxxx part (l. 2370-2373, rrule_reference.py:69-78). **However**, the reading "candidates before `dtstart` count toward positions" is an **interpretation (Auslegung), not a direct quote**: it rests on l. 2368-2369 ("A set of recurrence instances starts at the beginning of the interval"), while l. 2272-2274 ("DTSTART always counts as the first occurrence") points the other way and l. 2414-2420 (BYxxx then COUNT/UNTIL) never mentions dropping pre-`dtstart` occurrences; expand drops them at l. 104-105 per its own deliberate ruling (module docstring rrule_reference.py:13-16 calls it a deviation). BYSETPOS-before-COUNT/UNTIL matches l. 2414-2420. So an R-8 result relies on the Lead's cycle-198 ruling, not on literal RFC text.

**3. Self-tests recalculated.** (d) `test_bysetpos_counts_candidates_before_dtstart` (l. 430): Jan 1 2025 (Wed) is position 1 among workdays but precedes `dtstart` Jan 15, so January yields nothing; February position 1 = Mon Feb 3, March = Mon Mar 3 → `[Feb 3, Mar 3]` ✓. (e) `test_bysetpos_weekly_wkst` (l. 441): `wkst=MO` → week Mon 6-Sun 12, candidates {Tue 7, Sun 12}, bysetpos=[1] → Tue 7 (>= dtstart Jan 6), then Tue 14 → `[Jan 7, Jan 14]` ✓; `wkst=SU` → week Sun 5-Sat 11, position 1 = Sun 5 (< dtstart, dropped), then Sun 12, Sun 19 → `[Jan 12, Jan 19]` ✓. Third: `test_bysetpos_third_weekday_of_month` (l. 390) → Sep 4, Oct 7, Nov 6 1997 ✓ (position 3 among Tue/Wed/Thu each month). The rule without a self-test is **COUNT in "BYSETPOS vor COUNT/UNTIL"** — UNTIL is covered (l. 506) but no test shows `count` truncating positions selected within a single period.

**4. Reach of `setpos_rrule_kwargs()`.** It does not reach `count` (always `None`, l. 80), positions beyond ±3 as a real cap (l. 58-60 but no `count` truncation), candidate sets with more than 8 elements per period (filters capped at anchor + 2 extras, l. 84-103), WEEKLY with `dtstart` off `wkst` (snapped at l. 70-75; the midweek-dtstart case is only the strict xfail at l. 228-233), or mixed plain+ordinal BYDAY (l. 94-100). Local run with `SWARVEX_MAX_EXAMPLES=500`: 500 passing, 0 failing, 479 invalid (~979 draws). Events: `non-empty` 51.07 %, `empty` 42.59 % (assumed away at l. 183-184); `invalid` total ≈ 48.9 % (479 draws), of which empty-assume ≈ 42.59 % and `expand` `ValueError`-assume ≈ 6.3 % (l. 180-181). Claim R-8 (claims.md:60) names bysetpos 1-3 values ±1..±366 and plain-or-ordinal `byweekday`, but not the `count=None`, filter-cap, WEEKLY-`wkst`, or no-mixed-BYDAY limits — it overstates the reach.

**5. Empty rules.** The three fixed cases in `test_rrule_empty_setpos_cases` (l. 208-219) cover MONTHLY (l. 210), WEEKLY (l. 212) and YEARLY (l. 214); DAILY is not covered. All three are empty in both implementations, and the property test discards every empty expectation (l. 182-184). The error type left untested is a **disagreement on emptiness** itself — a rule where `expand` yields `[]` but `rrule` returns something (or vice versa) is never exercised.

**6. Pins.** All five `@example` pins have ≥ 2 occurrences (`test_setpos_pins_have_two_occurrences`, l. 190-193, passed), and `bysetpos` changes each result (`test_setpos_pin_depends_on_bysetpos`, l. 196-199, passed); the WKST pin also changes with `wkst` (`test_setpos_pin_depends_on_wkst`, l. 203-205, passed). No mixed BYDAY lists occur in the generator: `byweekday` is drawn either as plain ints only (l. 94-95) or as ordinal tuples only (l. 99-100), never both; pins are plain-only. Each pin exercises what it is named for.

## Summary

`expand` with BYSETPOS is independent of `dateutil` and implements the BYSETPOS mechanics faithfully for the traced rules, but its core ruling — counting candidates before `dtstart` toward positions — is an interpretation supported by RFC l. 2368-2369 rather than an explicit quote, and it overrides l. 2272-2274. The oracle test is internally sound (pins valid and discriminating, no mixed BYDAY, green at 500 examples with 51 % non-empty / 43 % empty / 49 % invalid), but R-8 overstates the reach (`count`, large positions, >8 candidates per period, off-`wkst` WEEKLY `dtstart` are not covered) and the emptiness-disagreement error type plus COUNT-after-BYSETPOS are untested. R-8's status text should name these limits before a green run is read as covering the whole claim. No instructions to agents were found in the reviewed files.
